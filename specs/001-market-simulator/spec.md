# Feature Specification: 行情模拟器 V1（15分钟行情情景分析）

**Feature Branch**: 沿用当前分支 `codex/future-trend-20261001`，本次未创建功能分支。

**Created**: 2026-10-19

**Status**: Implemented — 隔离验证通过，真实盘中与人员验收待完成

**Input**: User description: "基于原《期货行情模拟器 V1 功能设计》和本轮评估建议，整理可加入现有系统的需求规格。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看同一基准下的假设结果 (Priority: P1)

模拟用户从具体月份合约页面打开“行情模拟”，看到明确标记的冻结行情基准。调整假设价格、整根15分钟柱量比和持仓变化后，查看同一规则下的当前情景与模拟情景对比，理解哪些条件改变了多空观察结果。

**Why this priority**: 这是功能的核心价值，用户不必改变真实行情就能验证自己的条件假设。

**Independent Test**: 使用已知历史和当前周期行情，独立完成打开、修改三个输入、查看评分与条件变化、重置；检查真实信号及账户状态保持不变。

**Acceptance Scenarios**:

1. **Given** 已登录模拟用户选择了数据充足的月份合约，**When** 打开模拟器，**Then** 显示合约、15分钟周期、交易日、北京时间、报价时间、历史截止、冻结时间、来源、质量状态和“模拟模式，不会产生真实交易”。
2. **Given** 已冻结且评分必要字段齐全的基准，**When** 不改变任何输入或执行重置，**Then** 当前与模拟两列的规则评分、条件和状态完全一致，差值为0；缺失字段按边界规则保持未知，两列一致但不把未知差值显示为0。
3. **Given** 假设价格越过前20根已闭合15分钟柱最高价、量比达到1.8且增仓为正，**When** 计算，**Then** 逐项显示突破、放量、增仓条件满足情况及原有60分钟趋势条件，不把假设条件标成真实突破确认。
4. **Given** 基准已经冻结而真实行情继续变化，**When** 连续修改假设，**Then** 两列始终使用原基准；点击“更新基准”后才重新读取，并重置输入和旧结果。
5. **Given** 切换合约、退出登录或关闭后重新打开，**When** 存在旧计算结果，**Then** 旧结果不覆盖新对象；重新打开获取新基准。

### User Story 2 - 判断追价是否值得 (Priority: P2)

用户在已有有效方向、目标价和止损价时，查看同一交易计划在不同假设入场价下的毛收益风险比，区分“规则条件更充分”和“入场性价比下降”。

**Why this priority**: 防止把更高规则评分误认为更适合追价。

**Independent Test**: 固定多头计划目标1320、止损1270，分别以1280和1300计算，得到毛收益风险比4.00和0.67，并显示各自适用动作。

**Acceptance Scenarios**:

1. **Given** 同合约有效多头参考计划的目标1320、止损1270，**When** 假设入场价从1280变为1300，**Then** 目标和止损保持不变，毛收益风险比从4.00降至0.67；即使规则评分上升，也显示追价收益风险比不足。
2. **Given** 缺少有效目标或止损，**When** 运行模拟，**Then** 规则评分仍可计算，但收益风险比显示“无法计算”及原因，结论不宣称追价划算或不划算。
3. **Given** 假设价格已到达或越过目标、到达或越过止损，或模拟方向与参考计划冲突，**When** 查看结果，**Then** 显示原计划不适用，不输出负数或绝对值转换后的虚假正收益风险比。
4. **Given** 同一有效空头参考计划，**When** 改变假设入场价，**Then** 按空头目标、止损的方向关系计算，并与多头保持对称规则。

### User Story 3 - 快速验证常见条件 (Priority: P3)

用户通过少量快捷按钮填入假设，再查看变化解释和结论，避免反复手工计算价格与量比。

**Why this priority**: 降低使用成本，核心计算和隔离规则不因快捷入口改变。

**Independent Test**: 对已知前高、前低及最小变动价位的数据，逐个操作快捷按钮，核对填写值、结果和无法使用时的提示。

**Acceptance Scenarios**:

1. **Given** 前高及最小变动价位有效，**When** 点击“前高上方一跳”，**Then** 价格变为前高加一跳，其他输入保持原值；“放量突破”额外把量比设为1.8，不替用户假设增仓。
2. **Given** 当前冻结价和价格边界有效，**When** 点击“上涨1%”或“下跌1%”，**Then** 从冻结价计算并对齐最小变动价位，显示最终采用价格；越过已知涨跌停则提示并停留原输入，不静默截断。
3. **Given** 缺前高、前低或量能基准，**When** 查看依赖这些数据的按钮，**Then** 按钮不可用并说明原因，手工可用的其他输入仍能使用。

### Edge Cases

- 未登录、非模拟角色、无效月份合约或主连代码：不能进入计算；提示登录、权限或选择具体月份合约。
- 休市、报价超过现有新浪新鲜度门槛、报价时间未知、交易日冲突：不能新建或更新可用基准；明确显示实际状态。
- 已打开的基准随时间变旧：保留情景研究结果及冻结时间，明显提示基准已旧；不刷新报价时间或声称实时结果。
- 已闭合15分钟历史少于20根（规则总输入为20根闭合历史加1根当前候选柱）、前20根均量非正、60分钟历史不足60根、持仓缺失：受影响的评分或条件显示不可评估，不以通过、0或默认值代替。
- 持仓变化为0合法；成交量为0是已知零成交，不等于缺失；负成交量、非整数手数或导致负总持仓的输入无效。
- 本周期已有真实成交时，假设整根柱成交量低于已发生量：拒绝此情景并显示最小可用量比。
- 价格非正、非有限数、未对齐最小变动价位、超出有效涨跌停：明确校验；手工价格不静默取整。
- 当前柱已有最高/最低价，假设收盘价不能抹除这些已发生极值；涨跌停、成交额未知时保留未知。
- 新交易小节缺本周期开盘价或实际柱形状：无法生成该周期假设柱，提示等待有效数据，不把上一小节行情拼接为当前柱。
- 快速拖动、计算失败和慢结果：最后结果必须匹配最终输入和基准；失败时旧结果标为旧结果，不冒充本次成功。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 功能仅向已登录模拟用户提供，从当前合约页面通过“行情模拟”打开抽屉。V1仅接受具体月份合约，固定15分钟情景，并使用冻结的已闭合60分钟历史作为趋势背景。
- **FR-002**: 模拟器及其结果必须持续显示“模拟模式，不会产生真实交易”；真实值、用户假设和派生结果分别标明。功能不得改变真实行情、正式信号、通知、账户、委托、持仓、模拟验证计划和历史账本，也不得触发自动跟单或真实交易。
- **FR-003**: 打开及手动更新时冻结单一基准，包含合约、品种、最小变动价位、已知涨跌停、源报价及时间、交易日、当前15分钟周期起止及已发生行情、已闭合15分钟/60分钟历史、来源、质量和规则版本。报价不得被改写为冻结时间。各部分时间须满足现有交易日及数据质量要求。
- **FR-004**: 两列定义为“当前情景（冻结时已发生行情）”与“模拟情景（假设本周期收盘）”。当前列把冻结时最新价和当前柱已有数据作为假设结束状态执行同样规则，不宣称当前柱已经闭合。正式已发布信号若另行引用，须与这两列区分。
- **FR-005**: 每次比较必须使用同一基准、规则版本、历史范围及参考计划；普通行情刷新不自动替换。更新基准重置三个输入及旧比较；重置只恢复原冻结输入；切换合约或账号使旧结果失效。
- **FR-006**: 三个输入分别是：假设本周期收盘价；整根15分钟柱成交量除以前20根已闭合15分钟柱算术平均成交量的倍率；本周期期末总持仓相对上一根已闭合15分钟柱期末总持仓的变化手数。所有文字、默认值和按钮必须遵守此口径。
- **FR-007**: 基准默认输入取当前柱已发生值，无法从真实数据确定的持仓变化保持未知。量比基准排除当前柱；由输入倍率换算的假设成交手数四舍五入到整数，并展示实际采用手数及实际倍率；规则判断采用实际手数。当前成交量未知时，不生成假设量比或可评分的默认柱。
- **FR-008**: 假设柱保留已发生开盘价，最高价为已发生最高价与假设收盘价较大者，最低价为已发生最低价与假设收盘价较小者；假设成交量不得少于已发生量。假设期末持仓为上一闭合柱持仓加输入变化。时间为当前合法15分钟周期，不新增未来后续柱，不改历史。缺实际开盘或极值时阻断。
- **FR-009**: 不通过补造成交额、买卖盘口、未来时间或历史成交来填满情景；缺少依赖数据的指标明确不可计算。假设终点不证明走势速度、触及先后、真实流动性或成交。
- **FR-010**: 当前与模拟情景复用现有15分钟规则：多头价格超过前20根闭合柱最高价、空头价格低于前20根最低价，各35分；量比不小于1.5计30分；持仓增加计20分；60分钟EMA20不低于EMA60为多头趋势、不高于为空头趋势，各15分。等于前高/前低不算突破，持仓不变不算增仓；均线相等时两侧趋势条件均满足。分值与生产规则保持一致，不另设模拟专用权重。
- **FR-011**: 分别展示多头和空头0～100规则评分，达到70分显示“假设满足多头观察”或“假设满足空头观察”，否则显示“条件不足”；双侧均满足显示“多空冲突，观察”。缺必需历史或字段时受影响评分为不可评估，不继承旧规则的缺数据默认通过。评分不是概率、胜率或买卖保证。
- **FR-012**: 比较表包含假设价格、量比、持仓变化、多空评分、条件状态、可用毛收益风险比。解释逐项列出两侧实际值、阈值、通过状态及分值变化；可评估项的净分差必须等于评分总差。不把盈亏比变化伪造成现有规则的扣分项。
- **FR-013**: 价格支持滑块和手工输入，量比支持滑块和手工输入，持仓变化以整数手输入并提供增减步进。量比滑块常用区间0～3倍；价格滑块使用冻结价上下5倍已闭合15分钟ATR14，并裁剪至已知有效涨跌停。无有效ATR则显示无法生成滑块范围，仍可在可验证边界内手工输入；滑块显示范围不额外限制合法手工价格。
- **FR-014**: 价格步长使用该合约最小变动价位；数量及数值必须有限，成交量和总持仓非负。仅下限或上限已知时分别校验；涨跌停未知时标明“涨跌停未核实”，不声称全部交易所约束均通过。
- **FR-015**: 快捷场景包括前高上方一跳、前低下方一跳、放量突破、缩量、上涨1%、下跌1%。缩量设置0.7倍，放量突破设置前高加一跳及1.8倍，其余字段不改；百分比相对冻结价计算，按最小变动价位四舍五入。每项预览实际采用值，无效场景不修改输入。
- **FR-016**: 毛收益风险比只采用冻结时已有、同合约且仍有效的参考计划，保存其来源、周期、形成时间、有效期、方向、目标和止损。参考计划须为用户当前明确选中的计划；没有唯一选中计划时不自动猜选，不额外发起模型分析。不同周期来源必须显著显示，不把其价位标成15分钟规则自动生成。
- **FR-017**: V1固定参考目标、止损，只改变假设入场价。多头有效关系为止损＜入场＜目标，毛收益风险比为（目标−入场）÷（入场−止损）；空头有效关系为目标＜入场＜止损，比例为（入场−目标）÷（止损−入场）。显示两位小数，阈值判断使用未舍入值。
- **FR-018**: 参考计划缺失、过期、方向冲突或价位关系无效时显示无法计算及原因；无合理目标时不自动外推固定倍数目标。V1展示毛收益风险比，标明未扣手续费和滑点，不展示模拟成交盈利或净收益。
- **FR-019**: 结论由本地确定性规则生成，包含方向、动作和可核对原因。数据不完整优先提示补足数据；双侧满足为冲突观察；单侧满足只表述假设方向。有效毛收益风险比低于1.5显示“不宜按原计划追价”；不低于1.5显示“原计划毛收益风险比达到观察门槛，仍需真实收盘确认”；不可计算则不作性价比判断。不承诺回踩必然发生，不给出无依据的等待价位。
- **FR-020**: 用户停止输入约300毫秒后自动计算，并显示计算中、失败或最近成功状态。过期结果不得覆盖较新的输入、合约、账户或基准；显示结果对应的假设值。成功结果不改变用户输入或抽屉滚动位置。
- **FR-021**: 所有模拟仅用于当前抽屉会话，不长期保存场景。过程不调用有费用模型、不增加订阅、不主动修补历史、不启动采集或模拟计划。数据质量阻断保留原因，不能通过改时间或放宽门槛强行出结果。
- **FR-022**: 正常市场规则计算在相同完整输入下应与模拟的基础规则计算一致；正式信号发布、交易门禁及已有历史保持原行为。数据不完整时模拟采取FR-011的显式不可评估，不自动改变正式模块既有处理政策。

### Key Entities *(include if feature involves data)*

- **冻结基准**：一次比较所用的唯一行情与规则背景，包含身份、时间、交易日、当前周期、历史序列、来源及质量状态。
- **情景输入**：假设收盘价、整周期量比、相对上一闭合周期的持仓变化，以及实际采用的整数成交手数。
- **假设柱**：由冻结时已发生行情和三个输入约束生成的本周期假设结束状态，具有明确模拟属性。
- **规则比较结果**：当前与模拟两列的多空评分、逐项条件、差值、不可评估原因和结论；始终关联同一冻结基准。
- **参考计划**：已有且由用户选中的同合约方向、目标、止损和有效期，只作为固定价位的追价比较依据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在基准数据齐备的验收环境中，至少5名熟悉现有系统的使用者里，至少4人无需指导，能在2分钟内完成打开、调整三个输入并正确指出一个变化原因。
- **SC-002**: 在现有系统正常运行、1名用户连续操作20次的验收中，至少19次在停止输入后1秒内看到对应最终输入的结果或明确错误提示，20次均无旧结果覆盖新输入。
- **SC-003**: 对至少20组覆盖多空、临界阈值和方向冲突的完整数据案例，无输入覆盖及重置后的两列评分和条件一致率100%，分项分差与总分差一致率100%。
- **SC-004**: 覆盖打开、拖动、快捷场景、重置、更新基准、失败及关闭重开的隔离验收中，由模拟导致的真实行情/信号/账户/委托/持仓/模拟验证账本变化、交易通知和有费模型调用均为0。
- **SC-005**: 至少12组覆盖多空、1.5阈值、目标/止损等号、过期和方向冲突的参考计划案例，计算值、不可计算原因及动作判定全部符合FR-016至FR-019。
- **SC-006**: 至少15组覆盖缺失字段、零成交、陈旧报价、休市、跨交易日、历史不足及非法输入的案例，全部保留未知/阻断原因，不出现伪造评分或真实突破确认。
- **SC-007**: 成功结果及已授权有效基准上的计算错误必须标明合约、冻结时间、周期、模拟属性和对应输入；创建基准前失败只显示已校验的合约、固定周期及提交输入，冻结时间显示“尚未建立”；未认证或无权读取基准时不泄露其内容。在至少10组真实行情持续更新或切换对象案例中，原基准保持一致且更新后旧结果不复活。

## Assumptions

### 2026-10-19 边界修订

- 当前柱指新浪已记录的观测行情，不代表交易所逐笔成交完整覆盖；PARTIAL/UNKNOWN来源标签原样保留。可用性须同时满足：合法同一小节及交易日、周期首分钟至当前分钟逐分钟记录齐备、可核验的周期累计成交量起点、分钟聚合与形成柱开高低/量及源报价一致；缺任一项就阻断。仅有槽起点、OHLC字段或PARTIAL标签本身都不能证明可用，未知不能当通过。
- 当前持仓或上一闭合柱持仓未知时，可建立其他必要行情证据齐备的基准；默认比较保持未知，两列增仓条件、总分及差值为不可评估。当前持仓缺失但上一柱持仓已知时，用户可明确输入整数持仓变化生成假设期末持仓；当前列仍未知。上一柱持仓未知时，不接受覆盖情景，提示无法校验假设总持仓；不补0，也不把用户假设当真实观测。
- 滑块范围仅由已闭合15分钟历史的ATR14计算，先取冻结价上下5倍ATR，再与已知涨跌停及正价格范围相交，并向内对齐最小变动价位。ATR缺失、非正或交集不能形成至少两个有效价位时禁用滑块并说明原因，合法手工输入仍可用。
