# 未来趋势预测收尾开发计划

日期:2026-10-06。状态:本轮已收尾，以下保留原计划供追溯。用户后续授权由代理把控验收并放弃受阻项，实际执行范围与结果以[收尾开发验收](2026-10-06-未来趋势预测收尾-开发验收.md)为准；原提交、付费验收、跨日等待及用户页面补验安排不再作为本轮待办。CTP模块继续冻结。

## 0. 总体顺序与依赖

| 步骤 | 内容 | 前置条件 | 预估工作量 | 性质 |
| --- | --- | --- | --- | --- |
| 0 | 提交当前成果 | 无 | 10 分钟 | 立即执行 |
| 1 | SA/AP 期限依据与日历 | 无 | 0.5–1 天 | 外部依赖:CZCE 入口 |
| 2 | 行情逐行血缘与 JD 缺口核验 | 无 | 1 天 | 代码 + 数据核对 |
| 3 | 关联行情配置与 FU/BU 基本面 | 无 | 1–2 天 | 外部依赖:原报告 |

## 2. 步骤 1:SA/AP 期限依据与适用年份日历

目标:SA、AP 从 UNKNOWN 变为有来源的规则结果,或明确列出阻塞原因;UNKNOWN 不得冒充已核实。

处理:

1. SA(纯碱)、AP(苹果)均为郑商所品种。郑商所采集入口由用户继续研究;若用户提供入口,参照 `backend/ai_analysis/dce_api.py` 的模式新增 CZCE 适配(官方接口优先,记录原响应 hash 与核验时间,与 [LH/JD 证据](evidence/2026-10-06-contract-lifecycle/verification.md)同标准)。
2. 拿不到接口时,采用官方网页公告等可引用来源,同样保存原响应/截图、来源 URL、核验时间;仍拿不到则在期限状态中保留 UNKNOWN 并写明具体阻塞项,不算失败但也不标完成。
3. 适用年份日历只覆盖已核验年份;2027 年日历未核验前,2027 年目标日继续走"年份越界 → NO_JUDGMENT"路径,不套用旧年份假期。
4. 若期间出现 SA/AP 专项调整公告,按现有"专项公告优先于标准规则"机制填入配置,并保存公告原文证据。

修改入口:`config/future_contract_rules.json`、`backend/ai_analysis/future_trend.py`(仅当需要新来源适配时)、新增 CZCE 取证模块(如可行)。

验证:

- 服务 API 读回 SA/AP 期限状态为 VERIFIED(含依据与核验时间)或 UNKNOWN(含具体原因),二者必居其一。
- 离线边界测试补 SA/AP 用例(目标日在期限内/超限/年份未知),`.venv\Scripts\python.exe -m unittest discover -s tests -p "test_future*.py"` 通过。
- LH2611=2026-11-25、JD2612=2026-12-28 等既有结论不被改写。

## 3. 步骤 2:行情逐行血缘与 JD 缺口独立核验

目标:后续写入的每行行情可追溯来源与覆盖口径;JD 源 15m 缺口与跨周期成交量口径有独立核对结论。

处理:

1. 为非 CTP 历史入库链路建立逐行来源记录:来源、合约、时间戳语义(开端/结束)、夜盘归属、覆盖范围。先定位真实入库路径(`backend/collector/sina_collector.py` 及其写入端),复用现有字段优先,能不新增表就不新增表。
2. 建立"备份 → 预演 → 限定回补"流程:任何生产数据修复先备份受影响行,先在副本上预演,再限定合约/日期执行,保留修复记录。本轮仍不直接改生产数据。
3. JD 源 15m 缺 9/29 14:30、连续 17 根不足 20 根:独立核验是来源确实未提供还是采集遗漏;证据不足继续阻断,不放宽 20 根门槛放行。
4. 跨周期成交量口径差异候选(FU/BU 等)给出核对结论或保持"口径未核实"显示,不宣布检查通过。

修改入口:`backend/collector/sina_collector.py` 及其入库写入端、`backend/ai_analysis/snapshot.py`(仅当血缘需进入冻结输入时)。

验证:

- 构造含夜盘归属、午休、假期、缺口、跨缺口持仓差的本地 fixture,逐行血缘与质量状态可复现(同冻结输入得到相同结论)。
- JD 缺口有可追溯核对记录(证据文件),或明确标注证据不足维持阻断。
- 修复预演仅在备份副本上执行,生产库无未备份变更。

## 4. 步骤 3:关联行情配置与 FU/BU 基本面补缺

目标:目标合约的 `related` 不再全为空;FU/BU 关键指标逐项有状态(有效/缺失/期别未知/过期),有效项有原报告可溯。

处理:

1. 先小后大:只为步骤 4 首批验证涉及的 FU、BU、SA、AP 确认关联对象并配置(如 FU/BU→SC 能源参考),逐项验证"具体月份合约有数据、仍有效、适用关系成立";其余品种后续再配。没有可靠关联的品种允许空配置并说明原因,不为填满字段硬配。
2. FU 补中国进口/国内供应、船燃销售或加注需求的同源原报告;BU 补炼厂开工/产量统计期与道路施工量化需求的原始报告(23.4% 与 38.2 万吨需追回同源出处)。
3. 每项指标记录发布日期、数据期、核验时间,三者不编造;过期资料保留候选但不作为有效证据;国外数据不得充数中国指标。

修改入口:`backend/ai_analysis/web_research.py`、`backend/ai_analysis/research_cache.py`、`backend/ai_analysis/research_scheduler.py`、研究设置与关联配置。

验证:

- 服务 API 读回:目标合约 `related` 为 CONFIGURED 且关联行情有效,或 NOT_CONFIGURED 带原因;冻结输入中能看到关联数据。
- FU/BU 每个关键指标状态单独列示,不因库存有资料就宣称覆盖完整。
- 离线测试:期别移用、国外替代国内、过期证据三类反例仍被拦截,`test_web_research.py`、`test_research_credibility.py` 通过。

## 5. 步骤 4:小批真实模型验收(付费,先确认)

目标:按方案第 7 节完成真实验收,验证任务终态、规则门槛和内容质量,并检验压缩输入的真实理解效果。

前置:步骤 1–3 数据门槛满足(或受阻项以明确状态显示而非静默跳过);**用户确认付费预算后才开始**。

处理:

1. 范围:FU、BU、SA、AP 四合约 × 两模型,单次分析与复核;正常最多 16 次调用,另设最多 4 次全批补救调用;预算上限为上轮全量输入 token 量。
2. 报告模型 token、延迟与费用,分供应商列示,不把两家 token 计数当统一账单;未知用量列出估算误差。
3. AP 类连接失败沿用第 5 阶段有限重试与"结果未知"处理;一个模型/合约失败不阻断其他任务。
4. 通过后再扩到 8 合约,完整记录新增付费调用。

修改入口:原则上无代码改动;若验收暴露缺陷,修复后重跑受影响离线测试再重新小批验证。

验证:

- 全部任务有终态,结果 API 读回与库内一致;规则阻断任务零模型调用。
- 复核报告展示关键论断依据;压缩输入下的结果与未压缩基线无证据缺失(抽查关键数值与证据 ID)。
- 全过程调用日志保存(仅长度、耗时、状态、错误分类,不含凭据)。

## 6. 步骤 5:持续采集与来源验收

目标:东财占比达标(去重后 <60%),完成跨 2 个实际交易日的持续验收。

处理:

1. 复市后由现有调度器正常运行计划采集,至少 3 轮、跨 2 个实际交易日;不为验收高频访问官网。
2. 逐轮报告:URL 去重占比、同正文转载聚类后的来源分布、各品种有效指标覆盖、采集失败率;当前基线为东财 64%(150 篇中 96 篇)。
3. 不能删有效东财资料制造达标,不能把新增域名或转载当新增独立证据;三轮未达标则保留未完成状态并列出具体缺失来源与指标。

修改入口:原则上无代码改动;仅当调度器在复市后出现运行故障时修复。

验证:每轮产出一份来源分布报告;验收期结束后汇总,与 64% 基线对比。

## 7. 步骤 6:到期评估(10-12 / 10-14 之后)

目标:按冻结口径评估首批 3 日/5 日方向与区间命中。

处理:

1. 目标日收盘后,沿用冻结参考价与目标日收盘口径统计方向、区间命中、覆盖率及不判断比例;关联到当时冻结输入,不事后换合约或补资料。
2. 至少积累 20 个不同预测起点并披露重叠窗口后,才进入效果评价;该门槛只是开始评价的条件,不代表证明稳定盈利,证据完整度评分不叫胜率。
3. 届时如需评估脚本,作为独立小工具开发,不侵入交易与分析链路。
