# 定时公开资料采集与关联合约设置

日期：2026-10-02。状态：已实现并完成自动化、外部采集和服务验证；主服务页面验收由用户完成。详见 [实施与验证记录](../validation/2026-10-02-scheduled-public-research.md)。

用户已明确：两项都能设置，即定时检查哪些合约，以及预测每个合约时参考哪些关联合约。本方案替代原联网研究设计中“点击预测后再现场检索”的流程；已有来源核验、时间筛选、引用校验和预测规则继续适用。

## 1. 目标与方案选择

系统定时获取公开资料，点击“预测未来趋势”时直接读取有效资料并冻结，所有预测模型使用同一份输入。用户能控制采集范围、频率和研究模型，能看到本次实际采用的资料维度与关联合约。

推荐采用“独立采集名单 + 每个目标合约的关联设置”。另两种方式的取舍：

- 完全跟随自选：设置少，但增删自选会改变采集范围和模型调用成本，不适合作为默认。
- 全市场采集：覆盖广，但初期成本高、队列长，且大量资料不会使用，第一版不采用。

从自选导入是一次性复制；之后自选与采集名单分别维护。

## 2. 设置入口及交互

首页“模型设置”旁新增“资料采集”入口。设置面板包括：

| 设置 | 行为 |
| --- | --- |
| 开启定时采集 | 初始关闭；开启前必须有有效研究模型和至少一个目标合约 |
| 研究模型 | 从当前用户已有的模型配置中选择一个；与预测时选中的模型独立 |
| 采集间隔 | 15、30、60、120分钟；推荐默认60分钟，全名单采用同一间隔 |
| 采集合约 | 搜索具体合约、多选添加；也可“从自选导入” |
| 关联合约 | 在每个采集合约行中设置0至5个参考合约；显示具体交割月份 |
| 保存设置 | 校验成功后持久化，提示生效范围和去重后的实际采集品种数 |
| 立即更新资料 | 按已保存配置执行一次；定时关闭时仍可手动更新 |

合约行示例：

| 采集合约 | 预测时参考 | 资料状态 | 操作 |
| --- | --- | --- | --- |
| FU2611 | SC2611、BU2611 | 基本面可用，宏观可用，事件缺失 | 设置关联 / 更新该组 |
| BU2611 | SC2611 | 资料部分可用 | 设置关联 / 更新该组 |

关联关系是有方向的：FU→BU不代表BU→FU。预测FU只读取FU直接配置的关联，不递归追踪关联的关联。禁止引用自身，重复项自动去重。未配置关联时按目标合约自身分析。

保存前只展示配置预览，不启动任务。新增采集范围或更换研究模型后，对受影响主题安排下一次检查；仅调整关联顺序不触发重新采集。已有资料仍按适用范围和时效筛选。

研究模型不可用、被删除、被禁用或不支持工具时，显示具体原因并暂停自动调用；恢复配置后继续。禁止悄悄换成某次预测的模型。

## 3. 合约范围及资料共用

采集范围是“采集合约及其直接关联合约”的并集。资料实际检索按品种归并：FU2611与FU2612共用燃料油行业资料，每轮只检查一次FU；预测时仍按各自合约月份、适用期和目标日期筛选。

每轮任务包含：

1. 一份公共宏观主题，供当前用户所有合约使用。
2. 每个去重品种的基本面、事件、相关市场资料。

新增独立关联主题时也会检查对应品种。原油、美元等公开市场信息属于“相关市场”资料，不会自动生成新的国内关联合约。

品种资料包含库存、仓单、基差、供需、产销、进口、政策及行业事件；合约专项公告另记具体合约适用范围。仅有价格的综合日报不能证明基本面已经充分覆盖。

合约代码须在现有合约目录中校验。不接受未知代码、不自动替换交割月份、不自动换主力。已知到期合约提示更换并跳过相应引用；无法确认期限时明确标注“期限未核实”，沿用现有预测期限约束。

设置采集或关联不自动改变行情订阅。没有本地关联合约行情时，仍可使用其有效公开资料，并显示“行情缺失”；不会虚构价格、成交量和持仓。

## 4. 调度与执行

沿用后端启动/关闭生命周期增加轻量调度循环，不增加调度平台依赖。后台运行才会采集；关闭网页不影响任务，关闭服务会停止采集。

采集使用独立的单线程执行队列，避免占用现有预测执行池。数据库保存任务状态和时间。同一用户、同一主题只允许一个排队或执行中的任务；重复点击返回已有任务。

每个主题保留现有上限：最多90秒、3轮研究决策、8次搜索、12次网页阅读。公共宏观只研究宏观；品种任务只研究相应品种的外部维度，不重复请求公共宏观。复用现有受限联网工具，增加明确的主题/维度输入，不能伪称现有函数无需适配即可直接满足此流程。

队列按到期时间处理；过载时合并同主题的遗漏轮次，不累积补跑。每个主题结束后从完成时间计算下一次到期，失败也等到下一间隔，不循环立即重试。无新资料属于“检查完成，无新增”，区别于网络或模型失败。

数据库条件更新/租约负责认领任务，避免重复调度。进程崩溃或重启后将中断任务标为中断，不自动重发该次模型调用；已到期主题只排一次新检查，不补跑全部停机轮次。

每轮冻结配置版本与研究模型参数。配置在任务运行中变化时，旧任务保留审计，但不向当前可用资料发布新结果；下一轮使用新配置。关闭定时后不再认领任务，已在执行的任务可以结束并保留审计结果，不发布到可用缓存；移除范围后的资料不会进入该用户新预测。关闭前已发布的有效缓存仍可用于预测。

休市期间也按间隔检查公开资料，因为政策和行业事件可能在休市发布。第一版不增加复杂时段设置。

第一版定时研究仍可能调用AI，不能承诺“只有新增内容才调用AI”或必然降低费用。通过品种归并、宏观共用、限制频率及预测复用降低重复调用；统计实际研究调用、搜索、阅读、token和耗时。未来按固定站点增量抓取不属于本次范围。

## 5. 保存结构与时间规则

新增三类持久化记录即可，无需额外的资料平台：

| 记录 | 主要字段 |
| --- | --- |
| 用户采集配置 | owner、enabled、model_config_id、interval_minutes、合约及直接关联JSON、config_version、updated_at |
| 采集任务 | job_id、owner、topic、配置版本及模型快照、触发方式、状态、排队/开始/结束/下次检查时间、租约、工具记录、实际调用审计、资料版本ID列表、错误 |
| 资料版本 | material_id、owner、URL、标题、来源类型、正文及核验摘录、发布时间、数据期别、首次获取时间、版本获取时间、内容hash、维度、品种/合约适用范围、原始任务ID、宏观序列及最新发布核验信息 |

资料版本以同用户下的规范URL和内容hash去重；网页正文变化生成新版本，旧版本不覆盖。正文hash在摘要之前计算。每次重新核验、宏观最新发布核验的时间记录在任务结果中，不改写旧版本获取时间。

发布时间、数据期别、获取时间分别保存。重复读到旧报告不会让它变成新资料。AI整理文本只能辅助阅读，引用必须指向已保存的真实来源、版本和原文摘录。

沿用资料时间规则：基本面14个自然日，事件和相关市场7个自然日；宏观使用已核实的最新官方发布，不能简单按新闻有效期处理。宏观的最新发布核验超过两倍采集间隔后显示“最新发布待核验”，不再作为有效宏观证据。有效期第一版显示规则，不新增自定义设置。

历史资料保留以支持旧预测回看；新预测只使用发布时间及获取时间均不晚于预测截点的版本。网页修订后即使保留旧发布日期，新内容也不能进入早于修订获取时刻的预测。

任务成功不代表每个维度完整。更新时合并近期仍有效的已保存资料，不能因为新一轮没有搜到某维度就删除其旧有效资料；失败不覆盖有效缓存。未知日期、过期资料只作展开查看的背景，不作为有效预测依据。

## 6. 点击预测时的流程

1. 按现有逻辑校验目标合约和行情，确定预测截点、目标交易日及用户要求。
2. 读取当前用户配置；冻结目标合约的直接关联列表和配置版本。
3. 从已完成并发布的资料任务中，选择目标品种、明确匹配的合约专项资料、公共宏观及直接关联品种资料；以预测截点重新计算有效性。尚在执行的任务中间结果不使用。
4. 冻结关联合约已有的行情及其时间、来源和质量状态。仅取截点之前已闭合K线及不晚于截点的报价；闭市按现有规则保留最近有效数据。每个关联最多60根60分钟K线，计算持仓变化时额外读取前一根作为基准，不把缺失前值记作0。
5. 冻结完整资料包和hash后，提交各预测模型。包含源资料版本ID、实际选入摘录、适用合约、缓存状态和采集时间；以后更新资料不改变该批次。

冻结包设置输入上限：外部有效来源最多24条，每维度最多6条，单条摘录最多2000字符。优先目标合约的直接证据，再选公共宏观和明确相关证据；按适用范围、官方来源、发布时间排序，并保留被限额截断的数量。全文不随请求全部发送，用户展开时可查看保存正文和原始来源。

目标合约的技术与量价持仓来自自身行情。关联行情及关联公开资料均标明参考合约，不得拿SC的库存、成交量或持仓冒充FU的自身证据；设置关联不等于确认正相关，AI须说明关联作用与限制。

资料缺失或过期时可以启动基于有效行情的分析，但标明缺失维度；现有行情质量、合约期限和各期限投票门槛继续生效。行情不合格仍按原规则无法判断。

首次没有缓存、目标未配置、正在更新或上次失败，都不隐式启动搜索，也不等待采集。页面提示原因与“立即更新资料”；资料更新后由用户重新点击预测，新旧批次分别保留。修改设置不改变已经提交的预测。

## 7. 首页、未来趋势与历史展示

延续现有颜色和折叠规则，首页右侧和未来趋势统一展示。本次已提供资料与模型实际采用资料分别标注，避免把“缓存有资料”当成“模型已使用”。

预测前展示：

> 资料：部分可用 · 最近检查19:00 · 最近成功18:00 · 下次检查20:00
>
> 基本面：可用　宏观：待核验　事件：缺失　关联：SC2611、BU2611

预测结果展示：

> 已用：技术 · 量价持仓 · 基本面 · 相关市场（SC2611）
>
> 宏观缺失 · BU2611已提供但未引用

每个模型按经过校验的结果引用标记“已用”；仅关联设置中存在、不在实际引用中的合约不能显示“已用”。相关市场维度的使用不强制意味着用到了每个关联合约。

技术使用蓝色、量价持仓紫色、基本面青色、宏观橙色、事件琥珀色、相关市场靛色；缺失用灰色，过期/待核验用警示色。所有颜色同时配文字，不能只靠颜色传达含义。上涨下跌继续沿用已有方向配色。

默认只显示时间、状态、使用标签和关联合约。点击展开才能看到正文、来源URL、发布时间、数据期别、版本获取时间、实际引用及失败原因。搜索次数、阅读数量、研究模型与最近工具动作继续放在折叠详情中，任务结束后默认收起。

“最近检查”包括无新增的成功检查；“最近成功”指最近有有效资料产出的时间；二者与资料本身发布日期分开。采集状态和资料状态分别显示，例如“上次采集失败，缓存基本面仍有效”。

历史记录显示测算时间、目标日期、模型最新结果，并使用本批冻结的资料和关联关系，不读取当前设置来改写历史。预测计时保持从提交至本批结束，单独展示采集任务耗时。

## 8. 接口与现有代码接入

接口沿用当前模拟用户登录检查及owner隔离，后台以持久化owner执行，不依赖网页登录会话。研究凭据继续使用现有凭据引用，不返回前端、不写入资料正文。

- GET/PUT `/api/v1/ai/research/settings`：读取和保存当前用户配置；PUT带config_version，冲突时返回409并提示刷新。
- POST `/api/v1/ai/research/refresh`：全名单或一个已配置合约组手动更新；只认领已保存范围，不能绕过配置提交任意查询。
- GET `/api/v1/ai/research/status`：配置状态、各主题任务状态、时间、实际统计及按合约筛选的资料概况。
- GET `/api/v1/ai/research/materials/{material_id}`：所属用户的保存正文与版本信息。

接入点：

- `backend/models/database.py`及迁移：三类记录、唯一约束和查询索引。
- 新增资料采集模块：调度、范围归并、发布及截点选取；复用现有受限搜索/读取和研究审计。
- `backend/ai_analysis/web_research.py`：接受明确研究主题与维度范围，保持来源、预算、正文和日期核验。
- `backend/api/ai_routes.py`：设置/更新/状态接口，预测请求冻结缓存与关联。
- `backend/ai_analysis/snapshot.py`及`orchestrator.py`：将未来趋势的现场研究阶段替换为已冻结资料输入；补充关联快照和引用边界，保留预测、投票、复核逻辑。
- `backend/main.py`：采集任务生命周期管理。
- `frontend/index.html`：配置入口、合约选择、关联设置、缓存状态与使用标签。

旧历史中的现场检索记录继续展示。部署后不迁移旧预测快照，也不重新发起旧任务。

## 9. 验收条件

1. 设置FU2611→SC2611/BU2611及FU2612→SC2611，一轮只采集FU、SC、BU各一次、公共宏观一次；两份FU预测保留各自交割月份。
2. 只配置FU→BU时，预测BU不自动参考FU；关联不会递归，未知代码、自关联和超过5个关联被明确拒绝。
3. 从自选导入后再改变自选，不改变资料采集范围，也不自动新增行情订阅。
4. 同主题手动/定时重叠只执行一次；调度延迟、失败、重启不会补跑堆积轮次或重发中断调用。
5. 保存新范围时正在执行的旧配置结果不发布；关闭定时后不认领新任务；已提交预测保留原关联和资料版本。
6. 同URL同内容重复获取不生成新资料版本，修改内容保留新旧版本。新获取的旧报告不变新；预测截点后的内容不得进入输入。
7. 失败或无新增不会清空旧有效资料；旧资料按预测截点重新判断时效；宏观最新发布核验超期不能继续标记有效。
8. 点击预测无搜索/网页阅读调用，所有模型共享同一冻结包；空缓存、缺失关联行情及过期资料均准确标明。
9. 关联行情仅取已闭合且截点前的数据，前值缺失不伪造持仓变化，SC数据不能充当FU自身证据。
10. 首页与趋势标签以校验后的真实引用为准，展开可追溯原文与时间；研究日志结束默认折叠，历史不随资料更新变化。
11. 两个模拟用户不能查看或修改彼此配置、任务、正文与研究凭据；实际调用统计与真实执行一致，预算有效。
12. 用受控时钟、模拟模型和工具验证规则；另做一次真实公开网页采集及浏览器交互验收，分别报告本地测试和外网结果。

## 10. 范围

第一版仅覆盖未来趋势公开资料、定时检查配置及直接关联合约参考。CTP、实盘下单、自动交易、全市场爬取、自动发现关联、自动换月和其他分析类型不在本次设计范围内。
