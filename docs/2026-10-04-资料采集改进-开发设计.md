## 1. 硬性约束(违反任何一条即返工)

1. **CTP 冻结**:不碰 `backend/trade_engine/ctp_trader.py`、`backend/collector/ctp_collector.py`、`ctp_flow/`。
2. **安全边界不可削弱**:`web_research.py` 的 `_public_url`(仅 HTTPS 443、拒绝凭据)、`_professional_url` + `PROFESSIONAL_HOSTS` 白名单、SSRF/DNS-rebinding 防护(provider 的固定 IP 逻辑)、`MAX_BYTES=1MB`、编码识别失败即拒——全部保持原样,新代码只能复用不能绕过。
3. **不伪造数据**:来源打不开、解析失败、字段缺失,就登记失败/受阻事件(参照 `SHFE_BLOCK_EVIDENCE` 的做法),禁止编造数值或用替代数据冒充。
4. **预算模型不动**:单任务 90 秒 / 8 列表 / 8 搜索 / 12 正文 / 3 模型调用(`fixed_research.py` 的 `Budget` 与常量),新通道、新来源共享同一预算。
5. **调度与发布语义不动**:乐观锁、发布门、租约、`persist_sources` 的版本唯一键,不改。
6. **服务无热重载**:改了 `backend/` 必须执行 `stop.bat` → `start.bat` 重启;验证:`netstat -ano | findstr ":8000"` 有 LISTENING,`curl http://127.0.0.1:8000/api/v1/auth/me` 返回 401 JSON。
7. **测试框架是 unittest**(不是 pytest):`.venv\Scripts\python.exe -m unittest ...`;裸 `import test_bootstrap` 的模块用发现模式。

## 2. 任务一(P0):品种词表与相关性过滤修复

### 2.1 根因(已实测确认)

`backend/ai_analysis/future_trend.py` 的 `research_name()` 只对商品品种返回中文名:

```
IH2610 → 'IH'(无中文名)    JD2612 → '鸡蛋'    SA2701 → '纯碱'    FU2611 → '燃料油'
```

连锁反应(均已核实):

- `fixed_research.py:386-394` `rule_keywords()` 对无手工词表的品种生成 `f'{name} 库存 仓单 供需'` → IH 得到 "IH 库存 仓单 供需",对股指期货语义无效。
- `web_research.py:71-88` `_relevant()` 的匹配词 = `(name.lower(), instrument.lower()) + aliases.get(product)`;`aliases` 表(80-84 行)没有 IH/IF/IC/IM,也没有 JD/LH/SA/AP → IH 只匹配字面 "ih"/"ih2610",中文资讯里几乎不出现 → 候选全灭。

### 2.2 设计

**(a) 词表双轨制**:`RULE_KEYWORDS`(`fixed_research.py:25-30`)补两类条目:

- 金融/股指类(IH、IF、IC、IM):`fundamentals` 改用指数语义词(如 `'股指 贴水 升水 成交 持仓 两融'`),`events` 用 `'A股 政策 流动性 外围市场 央行'`。**禁止**给金融期货生成"库存/仓单"词。
- 农 products 补齐别名缺失的品种(JD、LH、SA、AP 至少这四个已配置品种):按现有 FU 条目的风格写 fundamentals/events 两组。

**(b) `research_name()` 注册中文名**:为 CFFEX 品种补中文名映射(上证50股指/沪深300股指/中证500股指/中证1000股指)。这是修 `_relevant` 的关键——匹配词要有 "上证50" 这类真实媒体用语。

**(c) `_relevant()` 的 aliases 表**(`web_research.py:80-84`)补齐:`'IH':('上证50','股指'), 'IF':('沪深300','股指'), 'IC':('中证500','股指'), 'IM':('中证1000','股指'), 'JD':('鸡蛋',), 'LH':('生猪','猪价'), 'SA':('纯碱','玻璃配合'), 'AP':('苹果','富士')`。与 (b) 保持一致,以 (b) 为主、(c) 兜底。

**(d) 不做的事**:不放松 `_relevant` 的整体逻辑(垃圾词拦截 73-74 行保留);不给金融期货开 86-87 行那种油系放宽(没有对应语义)。

### 2.3 测试与验收

- 单测:加到 `tests/test_fixed_research.py`、`tests/test_web_research.py`,至少覆盖:①IH 的 `rule_keywords()` 不含"库存/仓单"且含股指词;②`_relevant()` 对一篇标题含"上证50"的正文返回 True(用假 row,不联网);③JD/SA/AP/LH 的词表生成。
- 真实验收:重启服务后 `POST /api/v1/ai/research/refresh`(body `{}`),等 2 分钟,IH 主题出现 ≥1 条 fundamentals 或 events 资料(查 `GET /api/v1/ai/research/materials?topic=product:IH`);其余 223 项既有测试不回归。
- 登记基线对比:改后 Eastmoney 占比不上升。

## 3. 任务二(P1):搜索通道扩展,降低 Eastmoney 集中度

### 3.1 现状

`web_research.py:226-280` `search_public_web()`:先 Bing RSS(`https://www.bing.com/search?q=<site:限定>&format=rss`,site 列表 `SEARCH_SITES` 31-32 行),几乎总是空;兜底 Eastmoney 公开搜索 jsonp 接口 → 80% 资料来自东财。白名单 `PROFESSIONAL_HOSTS`(24-30 行)里 sina/qhrb/mysteel/oilchem/smm/99qh 等基本没被命中,因为**搜索入口**只有 Bing 和东财。

### 3.2 设计

在 `search_public_web()` 里把"东财兜底"改为"有序通道列表",通道间共享原预算与超时:

1. **Bing RSS**(保留,现状不变)。
2. **新增:新浪财经搜索**。候选接口形式 `https://search.sina.com.cn/?q=<kw>&c=news&sort=time`(无需 key,需先验证返回结构、确认可按时间排序、结果域含 `finance.sina.com.cn`)。**实现前必须真实请求验证一次并把验证记录写进交付说明**(日期、HTTP 状态、返回样例);验证不过就不接,登记受阻,禁止臆测接口格式上线。
3. **东财公开搜索**(保留,降级为通道 3)。

规则:

- 每通道独立 try/except,失败记事件(沿用 `search_warning`/FALLBACK 事件风格,`web_research.py:750` 附近有现成模式);一个通道失败不阻断后续。
- 候选合并后仍走现有去重、`_relevant`、时效过滤、`_source_scope`、白名单校验,通道本身不做相关性判断。
- `SEARCH_SITES`(Bing 的 site: 列表)可加 `finance.sina.com.cn`、`futures.com.cn`,但总 site 数 ≤ 12(Bing RSS URL 长度限制)。
- 每次搜索的候选数上限、每维度读 4 篇正文的上限不变。

### 3.3 测试与验收

- 单测(`tests/test_web_research.py`):模拟各通道返回(成功/空/抛错三态),断言:通道顺序、失败事件文案、合并去重、`search_provider` 字段标注。全部 mock,不联网。
- 真实验收:手动跑一轮采集,统计新入库资料的来源主机分布,`finance.eastmoney.com` 占比 < 60%(基线 80%);事件日志里能看到新通道的尝试记录。
- 诚实边界:若新浪接口实测不可用,允许交付"只完成通道框架 + 验证受阻记录",这算完成,不算失败。

## 4. 任务三(P2):仓单/库存固定源接入(优先郑商所/大商所)

### 4.1 现状与错位

`fixed_research.py` 的 `FIXED_SOURCES` 注册表(969-991 行,审查材料附录有全文)里仓单源只有 SHFE 且受阻(页面 Vue 前端渲染,静态读取无数据,2026-10-02 证据)。但**当前配置的 8 个品种里,仓单/库存数据最该接的是郑商所(SA、AP)和大商所(JD、LH)**——此前只盯着上期所是品种错位。

### 4.2 设计

**先调研后接入,每个来源一条真实验证记录**。候选入口(按优先级):

1. 郑商所每日仓单公告页(czce.com.cn,候选路径需实测;注意其网站有反爬与动态化先例,可能同样受阻)。
2. 大商所每日仓单/注册仓单页(dce.com.cn)。
3. 上期所仓单 data 接口的其他已知 URL 形态(如 `/data/dailydata/<日期>dailystock.dat` 变体、tsite 域名)——可再验一次,失败继续维持受阻登记。
4. 第三方公开页(99qh、mysteel)仅在前三类全阻后才考虑,且必须核对其数据确为交易所口径。

**接入方式 = 现有注册表模式,不造通用爬虫框架**(`FIXED_SOURCES` 注释原话"新增来源=新增一个带专用解析器的条目"):

- 每个新来源:`source_id`、`entry`、专用 parser(参照 `_parse_pbc`/`_parse_eia` 的写法,`fixed_research.py:1092-1160`)、`topics`/`products`、`series_id`、`enabled`。
- **新来源一律 `enabled=False` 起步**,解析器用保存的真实页面快照做 fixture 单测;真实验证(200 + 解析出品种行 + 日期字段)通过后才置 `enabled=True`,并把验证记录写进交付说明。
- 解析最小字段:品种代码、仓单量(或库存量)、数据日期、交易所;发布日期取页面公告日期,拿不到就 UNKNOWN(走现有 `published_at` 口径,不猜)。
- 阻复用现有受阻登记机制:`block_evidence` + `block_verified_on` + `enabled=False`。

### 4.3 测试与验收

- 单测(`tests/test_fixed_research.py`):每个解析器 ≥3 个 fixture 用例(正常、缺行、格式变化→抛 ValueError);`_source_applicable` 对新来源 products 的适用性。
- 真实验收:任一交易所源接通后,对应品种(如 SA)的冻结预览(`GET /api/v1/ai/research/status?instrument=SA2701`)出现官方仓单序列,`OFFICIAL` 来源、`fundamentals` 维度;页面"资料采集"弹窗该品种的待接入项减少。
- 汇报义务:三类交易所入口的验证结论(通/不通 + 证据)都要写出来,哪怕全部受阻。
