# 统计口径（Statistical Caliber）详解

日期：2026-09-14
适用范围：本期货实时交易系统 · 行情数据（`market_bar` / `market_tick`）
示例标的：燃油 2611（FU2611）

---

## 一、定义与作用

### 1.1 定义

**统计口径**是对一个数据指标做出的、**事先约定的一整套计算规则**。它回答六个问题：

| # | 问题 | 对应维度 |
|---|---|---|
| 1 | 统计的是多长一段时间？ | 时间粒度（period） |
| 2 | 这段时间的起点还是终点作为标记？ | 区间语义（bar_time） |
| 3 | 哪些时刻的数据入围？ | 统计范围 |
| 4 | 指标本身的单位与含义是什么？ | 变量定义 |
| 5 | 数据从哪来、怎么校验？ | 数据来源 |
| 6 | 多个层级之间怎么汇总？ | 聚合次序 |

**只要这六项中任一项不同，得到的数值就可能不同 —— 即使它们描述的是同一段时间的同一件事。**

### 1.2 作用

1. **可比性**：两个数字只有在口径一致时才能比较。否则差异来自口径而非事实。
2. **可复现性**：口径写死了，任何人在任何时间重算都能得到同一个数。
3. **可审计性**：对不上账时，能逐维定位是哪一环的口径没对齐。
4. **防误判**：避免把「口径差异」误判成「数据错误」而去做无谓的修数。

### 1.3 本系统的核心立场

> **口径不一致 = 结构性差异，不是「数据坏了」。**

本系统存在多条数据生成路径（新浪分钟接口、本地引擎从 tick 合成、日线接口），
它们的口径**天然不同**。看到数字不等时，第一步应是**对齐口径**，而非改数。

## 二、适用的统计范围与对象

### 2.1 对象维度

| 维度 | 取值 | 说明 |
|---|---|---|
| 合约 | `instrument_id` | 如 `FU2611`；主连 `FU0` 与主力同源 |
| 交易日 | `trading_day` | **交易日**语义，含前一自然日夜盘 |
| 周期 | `period` | `1m` / `5m` / `15m` / `30m` / `60m` / `1d` |
| 变量 | 见 §4 | OHLC、volume、open_interest、turnover |

### 2.2 交易日的边界（最易踩坑）

`trading_day = 20260914` 的 1m 序列**起点不是 09:00**，而是前一交易日（9/11 周五）晚 21:00：

```
交易日 20260914（共 345 根 1m）
├─ 首根  2026-09-11 21:00   ← 夜盘开盘
│  ...   21:00 ~ 22:59      120 根 · 434,177 手
├─ 09:00 2026-09-14 09:00   ← 日盘开盘
│  ...   09:00 ~ 14:59      225 根 · 807,026 手
└─ 末根  2026-09-14 14:59
────────────────────────────────────────
交易日记合计 = 1,241,203 手
```

**为什么这样设计**：期货的一个「交易日」是连续的——夜盘 + 次日日盘属于**同一个交易日**，
交易所的结算、涨跌停基准、持仓量变化都以交易日为单位。因此 `trading_day` 不能等于自然日。

### 2.3 交易时段（`period` 之外的独立维度）

| 时段 | 时间 | 1m 根数 |
|---|---|---|
| 夜盘 | 21:00 ~ 23:00（品种相关，SC/AU/AG 到 02:30） | 120 |
| 早盘前段 | 09:00 ~ 10:15 | 75 |
| 早盘后段 | 10:30 ~ 11:30 | 60 |
| 午盘 | 13:30 ~ 15:00 | 90 |
| （休盘） | 10:15~10:30、11:30~13:30 | 无数据 |

## 三、数据来源

| 来源 | 用途 | 口径特征 |
|---|---|---|
| 新浪分钟接口 `getFewMinLine` | 历史 1m / 5m / 15m / 30m / 60m | `d` 为**分钟结束**；`v` 为区间量 |
| 新浪日线接口 `getDailyKLine` | 日线校准 | 含完整交易日（夜盘+日盘） |
| 新浪实时报价 `hq.sinajs.cn` | 顶栏快照 | `v` 为**当日累计**，非区间量 |
| 本地 BarEngine（tick 合成） | 实时高阶周期 | **不含集合竞价** |

### 3.1 关键：三种 `v` 的含义完全不同

| 来源 | `v` 的含义 | 量级示例（FU2611 9/14） |
|---|---|---|
| 分钟接口 | **该分钟区间**的成交量 | 09:00 根 = 162,352（原始）/ 23,703（校正后） |
| 实时报价 | **当日累计**成交量 | 1,263,929 |
| 日线接口 | **该交易日累计**成交量 | 1,263,929 |

→ 把实时报价的 `v` 当成「分钟量」比较，是典型的口径误用。

## 四、指标的计算方式与公式

### 4.1 OHLC（价格）

设区间内包含的分钟集合为 `M = {m₁, m₂, …, mₙ}`（按时间升序），
分钟 `mᵢ` 的价格为 `(oᵢ, hᵢ, lᵢ, cᵢ)`：

```
Open  = o₁              （区间内第一分钟的开盘价）
High  = max(h₁ … hₙ)    （区间内所有分钟的最高价的最大值）
Low   = min(l₁ … lₙ)    （区间内所有分钟的最低价的最小值）
Close = cₙ              （区间内最后一分钟的收盘价）
```

**要点**：High/Low 取**极值**，不是平均，也不是首末值。

**实测校验**（FU2611 9/14 09:00~09:04 五根 1m → 5m 首根）：

| 字段 | 1m 五行聚合 | 新浪 5m 首根 | 一致 |
|---|---|---|---|
| Open | 4430（第一根 o） | 4430 | ✅ |
| High | 4458（五行 h 最大） | 4458 | ✅ |
| Low | 4396（五行 l 最小） | 4396 | ✅ |
| Close | 4440（末根 c） | 4440 | ✅ |

→ **OHLC 的聚合公式在两级周期之间是严格成立的。**

### 4.2 Volume（成交量）

```
Volume = Σ vᵢ   （区间内所有分钟成交量之和）
```

**要点**：Volume 是**累加**，这一条在理论上是守恒的——
但**实践中的不对齐主要就发生在 volume 上**，原因见 §6。

### 4.3 Open Interest（持仓量）

```
OpenInterest = OIₙ   （区间最后一分钟的持仓量，即期末值）
```

**要点**：OI 是**存量**指标，取**期末值**，**不累加**。
（错误做法：把各分钟 OI 相加 —— 那会得到无意义的巨大数字。）

**实测校验**（9/14）：
- 系统端 1m `open_interest` 范围：218,754 ~ 233,187
- 新浪 1m 源 `p` 字段范围：218,754 ~ 233,187 ✅
- 手机 App 副图 OI 轴读数：218,743 ~ 233,187 ✅

## 五、包含与排除的边界情况

### 5.1 包含

| 项 | 是否计入 | 说明 |
|---|---|---|
| 开盘集合竞价成交 | **计入 1m 首根** | 这是 1m 首根天然偏高的原因 |
| 休盘前最后一分钟 | 计入 | 如 10:15、11:30、15:00 |
| 尾盘集合竞价 | 部分计入 | 体现在 15:00 附近 |

### 5.2 排除

| 项 | 是否计入 | 说明 |
|---|---|---|
| 休盘时段（10:15~10:30、11:30~13:30、23:00~09:00） | **不计入** | 但**占据时间轴位置**（前端补空槽） |
| 非本交易日的夜盘 | 不计入 | 归属前一交易日 |
| 非交易时刻的源端脏数据 | 已过滤 | 如周六 09:00、周日 23:59 静态快照 |
| 撤销的委托 | **不计入成交量** | 成交量只统计**成交** |

### 5.3 关键边界：周期边界 vs 时段边界

**这是跨周期对账产生大额差异的根本原因。**

时段边界是 `09:00~10:15`、`10:30~11:30`、`13:30~15:00`，
而 `5m / 15m / 30m` 的边界是**整点/半点**（09:05, 09:10, …, 10:15, **10:35**, …）。

实测 5m 时间戳在休盘处的表现：

```
... 10:10, 10:15, 10:35, 10:40 ...   ← 跳过了 10:20~10:30（休盘）
```

13:35 同样：`... 11:30, 13:35, 13:40 ...` ← 跳过午休。

**后果**：
- `30m` 周期的边界（10:00、10:30）与时段边界（10:15、10:30）**不重合**，
  10:00 那根只覆盖 10:00~10:15 的 15 分钟，却被当作完整 30 分钟根 → 缺口巨大。
- 实测 09:00~10:15 区间：`30m` 归集量 408,170，比 `1m` 少 **25%**。

## 六、与其他口径的区别与常见注意事项

### 6.1 实测差异量化（FU2611 9/14 同区间 09:00~10:15）

| period | 归集量 | 相对 1m | 主要差异来源 |
|---|---|---|---|
| 1m | 546,979 | — | 基准 |
| 5m | 543,344 | −0.7% | 边界含/不含 + 采样残差 |
| 15m | 522,174 | −4.5% | 边界错位 |
| 30m | 408,170 | **−25%** | 边界跨越 10:15 休盘 |
| 60m | 25,943 | 完全错位 | 边界与时段无对应关系 |

### 6.2 三个差异来源（按影响量级）

**① 周期边界 vs 时段边界不对齐（主因，大额差异）**

见 §5.3。周期越长，跨界那一根的占比越大，误差越显著。

**② 含/不含开盘集合竞价**

1m 首根含竞价（正常日约 1.4~1.5x 次高，异常时可达 10x）；
高阶周期若由本地引擎从 tick 合成，则**不含**竞价。

**③ 源端独立采样残差（小额但普遍）**

新浪 1m 与 5m 是**两套独立聚合**，不是同一份数据的两种视图。

实测逐根配对（5m[k] vs 对应 5 行 1m 之和），45 根中：

| 检验 | 命中 |
|---|---|
| 与「5 行 1m 之和」相等 | **0 / 45** |
| 与「同刻单行 1m」相等 | 8 / 45 |

典型样例：

| 时刻 | 5m 根 | 对应 5 行 1m 之和 | 差 |
|---|---|---|---|
| 14:40 | 1,806 | —（同刻 1m = 1,806） | 点采样特征 |
| 14:45 | 2,727 | 11,652 | **−8,925** |
| 全天累积 | — | — | **−85,208**（约 −10.6%） |

**④ 源端存在稀疏/近零根**

5m 序列中出现与相邻根量级差一个数量级的极低值：

```
11:00 → 692      11:05 → 279      14:00 → 179
14:20 → 141      14:25 → 79       15:00 → 93
```

相邻根通常在 5,000~20,000 量级。这说明源端推送的是**部分窗口**，
不是真实成交骤降 —— 不可据此判断行情。

### 6.3 常见注意事项（对账铁律）

| # | 铁律 | 反面例子 |
|---|---|---|
| 1 | **`bar_time` 语义必须先统一** | 新浪原始 `d` 是「分钟结束」，本地是「分钟起始」；直接按字符串比会整体错位一格 |
| 2 | **不要跨周期直接相减** | 「5m 某段之和」vs「1m 某段之和」，除非常数对齐全部边界维度 |
| 3 | **不要拿分钟合计与日线相减** | 见 §6.4 |
| 4 | **OI 取期末值，不要累加** | 累加会得到无意义巨数 |
| 5 | **区分「区间量」与「累计量」** | 实时报价的 `v` 是当日累计，不是分钟量 |
| 6 | **先对齐口径，再判定异常** | 看到数字不等就改数，可能改坏正确数据 |
| 7 | **归一化后再比较** | 用「倍数」「占比」等无量纲比值，可绕开绝对量口径差 |

### 6.4 典型误区：1m 合计 vs 日线 volume

| 项 | 值 |
|---|---|
| 新浪 1m 9/14 全天合计 | 807,026 |
| 新浪日线 9/14 `v` | 1,263,929 |
| 直接相减 | 456,903 ❌ **错误比法** |

**原因**：1m 接口返回的是「9/14 当天」的数据（日盘为主），
而日线 `v` 覆盖的是**完整交易日**（含 9/11 的夜盘）。

**正确比法**：

```
交易日记合计 = 夜盘(9/11) 434,177 + 日盘(9/14) 807,026 = 1,241,203
与日线 1,263,929 差 22,726（1.80%，属正常口径差）
```

## 七、具体示例：一次完整的口径对齐过程

### 场景

用户反馈「FU2611 9 点那根柱子不对」。要求判断是**数据错误**还是**口径差异**。

### 步骤

**Step 1 — 锁定对象**
- 合约 `FU2611`，交易日 `20260914`，周期 `1m`
- 目标根：`bar_time = 2026-09-14 09:00`

**Step 2 — 确定「第一根」到底是哪根**

| 候选 | 时刻 | 说明 |
|---|---|---|
| 交易日首根 | 09-11 21:00 | 夜盘开盘 |
| 日盘首根 | 09-14 09:00 | 用户所指 |

→ 必须区分，否则核对对象就错了。

**Step 3 — 统一时间戳语义**

新浪原始 `d = "2026-09-14 09:01:00"`（分钟结束）
→ 对应本地 `bar_time = "2026-09-14 09:00:00"`（分钟起始）
→ 才能正确配对。

**Step 4 — 逐字段核对**

| 字段 | 系统端 | 新浪源 | 一致 |
|---|---|---|---|
| O | 4430 | 4430 | ✅ |
| H | 4442 | 4442 | ✅ |
| L | 4405 | 4405 | ✅ |
| C | 4410 | 4410 | ✅ |
| **V** | **23,703** | **162,352** | ❌ |
| OI | 219,706 | 219,706 | ✅ |

→ 唯一差异在 volume，其余五项全对。

**Step 5 — 用无量纲比值判断 volume 是否异常**

同一合约历史正常日的「首根 ÷ 当日次高」：

| 交易日 | 首根 | 次高 | 倍数 |
|---|---|---|---|
| 09-10 | 11,545 | 8,537 | 1.4x |
| 09-11 | 27,639 | 18,126 | 1.5x |
| **09-14** | **162,352** | **15,802** | **10.3x** ← 异常 |

→ 正常日稳定 1.4~1.5x，本日 10.3x。**这是异常，不是口径差。**
（用「倍数」而非绝对量，绕开了不同合约/不同日的量级差异 —— 即 §6.3 铁律 7）

**Step 6 — 确认总量守恒，排除数据损坏**

| 项 | 值 |
|---|---|
| 新浪 1m 9/14 日盘合计 | 807,026 |
| 系统端校正后日盘合计 | 807,026 |

→ 总量分毫未变 → **总量没坏，坏的是「量在分钟之间的分配比例」**。

**Step 7 — 得出结论**

- **是数据错误**：源端把集合竞价累计量错写入首根，导致量级失真 10 倍。
- **不是口径差异**：因为 OHLC/OI 全对、总量守恒，仅分配比例异常。
- **处置**：校正首根（`23,703 = 次高 15,802 × 基准 1.5`），差额摊回后续分钟，保持合计不变。

### 对比：如果这是口径差异会怎样

| 情形 | 表现 | 处置 |
|---|---|---|
| **数据错误** | 总量守恒，单根量级失真 | 修正该根 |
| **口径差异** | 同一区间不同周期总量不同（如 30m 比 1m 少 25%） | **不改数**，对齐口径后再比 |

判别关键：**看总量是否守恒**。
- 守恒 → 分配问题（数据错误）
- 不守恒 → 边界/范围问题（口径差异）

## 八、速查表

| 指标 | 聚合公式 | 要点 |
|---|---|---|
| Open | 区间第一根的 `o` | 首值 |
| High | `max(hᵢ)` | 极值 |
| Low | `min(lᵢ)` | 极值 |
